Technical & Operational Specification 2026

ระบบปรับปรุง ยี่ห้อ (BRAND), ประเภทสินค้า (SKU_CAT) และ รายละเอียด (DETAIL) ตามรหัสสินค้า (SKU_CODE)

1

วัตถุประสงค์และแนวคิดการทำงาน (Concept & Objectives)

ที่มาของปัญหาและความสำคัญของการปรับปรุงข้อมูล Master Sales Data

ปัญหาเดิมที่พบในระบบ:
  • ในตารางประวัติการขาย ims_data_sale_sac_all มักมีข้อมูลรายการสินค้าที่ฟิลด์ BRAND (ยี่ห้อ), SKU_CAT (ประเภท) หรือ DETAIL ไม่สมบูรณ์, ค่าว่าง, หรือสะกดไม่เป็นไปตามมาตรฐาน
  • ส่งผลให้หน้าจอรายงานและระบบวางแผนการขาย เช่น Export ข้อมูลยอดขาย สำหรับ PLAN ยาง (export_data_v_template.php) และ Volume Tires Plan (forecast_plan_display_volume_tires.php) ที่มีการกรองเงื่อนไข:
    BRAND: VB, ATLAS, AT, BS/FS ฯลฯ SKU_CAT: TBR/LTR, LSR, TBB/LTB
    ไม่สามารถดึงยอดขายของสินค้านั้นๆ ออกมาได้อย่างครบถ้วน
  • หากต้องตามแก้ไขทีละบิลในระบบบัญชีเดิมจะใช้เวลานานมากและไม่ทันต่อรอบการทำแผน Forecast
แนวคิดการแก้ปัญหา (Solution Architecture):
  • สร้างหน้าจอ Excel Import Batch Update ตามรูปแบบของหน้าจอมาตรฐาน update_data_import_cust_sale_sac_2.php
  • ใช้ รหัสสินค้า (SKU_CODE) เป็น Primary Key ในการค้นหาและอัปเดตข้อมูลทุกแถวในตาราง ims_data_sale_sac_all พร้อมกันในคำสั่งเดียว
  • ใช้โครงสร้างไฟล์ Excel กระชับเพียง 3 Fields (คอลัมน์ A, B, C):
    1. SKU_CODE (คอลัมน์ A) : รหัสสินค้าที่ใช้ค้นหา (Key)
    2. BRAND (คอลัมน์ B) : ยี่ห้อสินค้าตามมาตรฐานใหม่
    3. SKU_CAT (คอลัมน์ C) : ประเภทสินค้าหลัก (และระบบจะดูแลฟิลด์ DETAIL ให้สอดคล้องกัน)
  • มีระบบบันทึกประวัติการนำเข้าลงตาราง log_import_data พร้อมแสดงตารางสรุปข้อมูลสินค้าในระบบด้านล่างทันที
ตารางฐานข้อมูลเป้าหมาย: ตาราง ims_data_sale_sac_all ซึ่งเป็นตารางคลังข้อมูลยอดขายกลาง (Sales Data Warehouse) ของบริษัท SAC ที่ทุกระบบนำไปใช้ประมวลผลต่อ

โครงสร้างไฟล์ Excel สำหรับนำเข้า (Excel Template Specification)

รูปแบบตารางและชื่อหัวคอลัมน์มาตรฐาน (Row 1 ในไฟล์ Excel)

ไฟล์ Excel ที่จะนำเข้าจะต้องเป็นไฟล์นามสกุล .xlsx หรือ .xls โดยมีโครงสร้างหัวตารางใน แถวที่ 1 (Row 1) ดังนี้:

คอลัมน์ ชื่อหัวข้อ (Header) ฟิลด์ฐานข้อมูล คำอธิบายข้อมูลและเงื่อนไข ตัวอย่างข้อมูล
A รหัสสินค้า Key SKU_CODE รหัสสินค้าในระบบ (ห้ามเว้นว่างเด็ดขาด) ใช้เป็นเงื่อนไขในการค้นหาเพื่ออัปเดตข้อมูลทุกบิล AT1122516-AP200
VB10002016-LUG
B ยี่ห้อ (BRAND) Update BRAND ชื่อยี่ห้อที่ต้องการปรับปรุง เช่น ATLAS, VB, BS/FS, DS, DL ATLAS
C ประเภทสินค้า (SKU_CAT) Update SKU_CAT ประเภทยาง เช่น TBR/LTR (ยางใหญ่), LSR, TBB/LTB (ยางผ้าใบ), ยางเล็ก (ระบบจะซิงก์ DETAIL ให้สอดคล้องกันอัตโนมัติ) TBR/LTR (ยางใหญ่)
ข้อควรระวังสำคัญในการเตรียมไฟล์:
  • แถวที่ 1 (Row 1) ต้องเป็นหัวคอลัมน์ ห้ามผสานเซลล์ (Merge Cells) และต้องมีคอลัมน์ A เป็น รหัสสินค้า
  • ข้อมูลที่จะถูกอัปเดตจะเริ่มอ่านตั้งแต่ แถวที่ 2 (Row 2) เป็นต้นไป
  • หากแถวใดไม่มีค่าในคอลัมน์ A (รหัสสินค้าว่าง) ระบบจะข้ามแถวนั้นไปโดยอัตโนมัติ

วิธีการทำงานระดับเทคนิคและฐานข้อมูล (Technical Architecture)

เบื้องหลังการทำงาน การจัดการหน่วยความจำ และความปลอดภัยของข้อมูล

1. คำสั่ง SQL สำหรับอัปเดตข้อมูล (Prepared Statement):
UPDATE ims_data_sale_sac_all
SET BRAND = :BRAND,
    SKU_CAT = :SKU_CAT,
    DETAIL = :DETAIL,
    SKU_NAME = COALESCE(NULLIF(:SKU_NAME, ''), SKU_NAME),
    seq_record = :seq_record,
    update_date = NOW()
WHERE SKU_CODE = :SKU_CODE;
2. มาตรการความปลอดภัยและประสิทธิภาพ (Safety & Performance):
  • Database Transaction (ACID): ใช้ $conn->beginTransaction() ครอบการทำงาน และ $conn->commit() ทีเดียวเมื่อเสร็จสิ้น หากเกิดข้อผิดพลาดจะ $conn->rollBack() ข้อมูลจะไม่เสียหาย
  • Dynamic Memory & Execution Time: ปลดล็อก set_time_limit(0) และ ini_set('memory_limit', '2048M') รองรับไฟล์ Excel ที่มีจำนวนหลายหมื่นแถวได้อย่างเสถียร
  • MIME Type Validation: ตรวจสอบความถูกต้องของไฟล์ผ่าน finfo_file() ป้องกันการอัปโหลดไฟล์แปลกปลอม
  • Log Auditing: บันทึกประวัติการนำเข้าลงตาราง log_import_data ระบุชื่อไฟล์, จำนวน Record, วันเวลา, และผู้ใช้งาน (Create By)
3. การซิงค์ต่อเนื่อง (Optional Auto-Sync to Master Products):

สามารถเชื่อมโยงอัปเดตตาราง Master สินค้า ims_product หรือ m_volume_tires เพื่อให้ข้อมูลยี่ห้อและประเภทตรงกันทั้งระบบโดยอัตโนมัติ
