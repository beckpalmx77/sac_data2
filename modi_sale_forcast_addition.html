บันทึกประวัติการปรับปรุงระบบวางแผนการขาย (Forecast Plan)

การเปิดให้คีย์แก้ไข "เป้ารายเดือน" และ "แพลนยาง" สามารถ Save ข้อมูลได้อิสระแต่ละรายการ และแยกปุ่ม "ยืนยันล็อคเดือนนี้" ครอบคลุมทั้งระบบยางเล็กและระบบยางใหญ่ (Big Tires)

วันที่ปรับปรุงล่าสุด: 2 ตุลาคม 2026 ระบบ: SAC Data2 (Tires & Big Tires Forecast Realtime) ฐานข้อมูล: sac_data2 (192.168.88.7:3307) สิทธิ์ควบคุม: Admin / Sale Supervisor / Sale User
เปิดให้คีย์ข้อมูล
เป้ารายเดือน และ แพลนยาง แก้ไขได้โดยตรงบนตาราง ทั้งยางเล็กและยางใหญ่
Save แต่ละรายการได้
กดปุ่ม "บันทึก" รายแถว หรือ "บันทึกทั้งหมด" ได้เรื่อยๆ โดยยังไม่ล็อค
ยืนยันล็อคทีเดียว
กดปุ่ม "ยืนยันล็อคเดือนนี้" เมื่อกรอกและตรวจสอบข้อมูลเสร็จสมบูรณ์
สิทธิ์ปลดล็อค
Admin / Sale Sup สามารถสั่ง "ปลดล็อคเดือนนี้" เพื่อเปิดให้แก้ไขย้อนหลังได้
1. วัตถุประสงค์และความต้องการ (Objectives)
  1. เปิดคีย์ข้อมูล 2 คอลัมน์สำคัญ: บนหน้าจอ forecast_plan_display_realtime.php (ยางเล็ก) และ forecast_plan_display_realtime_big_tires.php (ยางใหญ่) ต้องการเปิดให้พนักงานขายสามารถกรอกและปรับเปลี่ยนตัวเลข "เป้ารายเดือน" (target_qty_month) และ "แพลนยาง" (forecast_qty_month_1) ได้โดยตรง
  2. Save ข้อมูลแต่ละรายการโดยยังไม่ล็อค (Incremental Save): ให้ผู้ใช้สามารถกดบันทึกข้อมูลแต่ละแถวผ่านปุ่ม บันทึก ประจำรายการ หรือกดปุ่ม "บันทึกการแก้ไขทั้งหมด" ได้ตลอดเวลา โดยระบบจะบันทึกตัวเลขลงฐานข้อมูลทันที แต่ยังคงสถานะ is_locked = 0 ไว้ เพื่อให้สามารถกลับมาคีย์ต่อหรือปรับแต่งตัวเลขได้ตามต้องการ
  3. ยืนยันการล็อคทีเดียวผ่านปุ่มควบคุมเฉพาะ: เมื่อทำการกรอกและตรวจสอบตัวเลขเรียบร้อยแล้ว จึงกดปุ่ม "ยืนยันล็อคเดือนนี้" เพื่อล็อคข้อมูลทั้งหมดของเดือนนั้นในคราวเดียว (is_locked = 1) ป้องกันการแก้ไขย้อนหลัง
  4. การควบคุมสิทธิ์ (Permission Control):
    • พนักงานขาย (Sale User): บันทึกข้อมูลได้อิสระ และเมื่อเสร็จสิ้นสามารถกด "ยืนยันล็อคเดือนนี้" ของตนเองได้
    • ผู้ดูแลระบบ/หัวหน้างาน (Admin / Sale Sup): สามารถสั่ง "ยืนยันล็อคเดือนนี้" และเป็นกลุ่มเดียวที่สามารถกดปุ่ม "ปลดล็อคเดือนนี้" ได้
2. การปรับปรุงโครงสร้างฐานข้อมูล (Database Schema)

ทำการเพิ่ม 3 ฟิลด์ใหม่ในทั้ง 2 ตารางหลัก (ยางเล็กและยางใหญ่) บนฐานข้อมูล sac_data2 (MySQL 192.168.88.7:3307):

ตารางยางเล็ก (Small Tires)
ALTER TABLE ims_tires_plan_forecast_realtime ADD COLUMN is_locked TINYINT(1) NOT NULL DEFAULT 0, ADD COLUMN locked_at DATETIME NULL, ADD COLUMN locked_by VARCHAR(100) NULL;
ตารางยางใหญ่ (Big Tires)
ALTER TABLE ims_tires_plan_forecast_realtime_big_tirs ADD COLUMN is_locked TINYINT(1) NOT NULL DEFAULT 0, ADD COLUMN locked_at DATETIME NULL, ADD COLUMN locked_by VARCHAR(100) NULL;
ชื่อฟิลด์ ประเภทข้อมูล ค่าเริ่มต้น คำอธิบาย
is_locked TINYINT(1) 0 สถานะการล็อค (0 = สามารถแก้ไขและ Save ได้, 1 = ถูกล็อคห้ามแก้ไข)
locked_at DATETIME NULL วันเวลาที่มีการกดยืนยันล็อคข้อมูล (TIMESTAMP)
locked_by VARCHAR(100) NULL Username ของผู้ที่ทำการกดยืนยันล็อค
3. รายการไฟล์และรายละเอียดการแก้ไข (Source Code Changes)
ก. ระบบยางเล็ก (Small Tires)

  • เพิ่มปุ่มบันทึกแต่ละรายการ: เพิ่มปุ่ม บันทึก (ปุ่มสีเขียว btn-save-row-inline) ในคอลัมน์จัดการของทุกแถวที่ยังไม่ล็อค เพื่อให้ผู้ใช้สามารถคลิกเซฟแถวนั้นได้ทันที
  • ปลดล็อค input: นำแอตทริบิวต์ readonly ออกจาก target_qty_month และ forecast_qty_month_1 เมื่อ is_locked == 0
  • การแสดงผลเมื่อล็อค: ถ้า is_locked == 1 จะใส่ readonly, คลาส locked-input, ไอคอน 🔒 ที่ SKU และเปลี่ยนปุ่มจัดการเป็นป้ายสถานะ ล็อค

  • แยกปุ่มควบคุมบน Toolbar:
    • ปุ่ม บันทึกการแก้ไขทั้งหมด: เซฟข้อมูลทุกแถวบนตารางโดยไม่ล็อค
    • ปุ่ม ยืนยันล็อคเดือนนี้: แสดงข้อความยืนยันการล็อคทั้งเดือน เมื่อกดยืนยันจึงจะตั้งค่า is_locked = 1
    • ปุ่ม ปลดล็อคเดือนนี้: สิทธิ์เฉพาะ Admin / Sale Sup
  • รองรับการคลิกบันทึกเฉพาะรายการ (Inline Save): ผูก Event กับ .btn-save-row-inline บันทึกเฉพาะข้อมูลแถวนั้น และแสดง Toast แจ้งเตือนสวยงาม

  • ยกเลิกการตั้งค่า is_locked = 1 ในการ Save: ปรับปรุง SQL UPDATE ให้บันทึกเฉพาะตัวเลขเป้าหมาย, แพลน, หมายเหตุ โดยไม่ปรับเปลี่ยนสถานะการล็อค ทำให้ผู้ใช้บันทึกซ้ำได้เรื่อยๆ
  • Backend Guard: ตรวจสอบว่า หากรายการดังกล่าวมีสถานะ is_locked = 1 อยู่แล้ว และผู้ใช้ไม่ใช่ Admin จะปฏิเสธการแก้ไขทันที

  • รองรับการกดยืนยันล็อคทีเดียว (action=lock): บันทึก is_locked = 1, locked_at = CURRENT_TIMESTAMP, locked_by = $_SESSION['alogin']
  • คำสั่งปลดล็อค (action=unlock): อนุญาตเฉพาะผู้ใช้ระดับ admin และ sale_sup เท่านั้น
ข. ระบบยางใหญ่ (Big Tires)

  • เพิ่มปุ่มบันทึกแต่ละรายการ: มีปุ่ม บันทึก (btn-save-row-inline) ในทุกแถวที่ยังไม่ล็อค
  • เปิดช่องคีย์: ปลด readonly ในช่องเป้ารายเดือนและแพลนยางเมื่อ is_locked == 0

  • แยกปุ่มควบคุมบน Toolbar: มีปุ่ม "บันทึกการแก้ไขทั้งหมด" (ไม่ล็อค) และปุ่ม "ยืนยันล็อคเดือนนี้" แยกออกจากกันอย่างชัดเจน
  • รองรับการคลิกบันทึกแต่ละแถว: ทำงานผ่าน Event .btn-save-row-inline เซฟเฉพาะแถวนั้นได้ทันที

  • บันทึกข้อมูลโดยไม่ล็อค: ปรับปรุง UPDATE ใน ims_tires_plan_forecast_realtime_big_tirs โดยไม่ใส่ is_locked = 1
  • Backend Guard: ป้องกันไม่ให้แก้ไขแถวที่ถูกล็อคแล้ว

  • ระบบล็อค/ปลดล็อคตามคำสั่ง: สั่งล็อคเมื่อกดปุ่มยืนยัน หรือปลดล็อคเฉพาะผู้มีสิทธิ์ Admin / Sale Sup
4. ขั้นตอนการใช้งานจริง (Workflow Guide)
ขั้นตอนการคีย์และ Save (ระหว่างทำงาน)
1
เลือก เดือน และ ปี ที่ต้องการวางแผนการขาย
2
กรอกตัวเลขในช่อง "เป้ารายเดือน" และ "แพลนยาง" ตามต้องการ ระบบจะคำนวณและซิงค์ยอดร้านค้าให้อัตโนมัติ
3
การบันทึก:
  • คลิกปุ่ม บันทึก ท้ายแถว เพื่อเซฟเฉพาะแถวนั้น
  • หรือคลิกปุ่ม บันทึกการแก้ไขทั้งหมด เพื่อเซฟทุกแถวบนหน้า
  • * การบันทึกขั้นตอนนี้จะยังไม่ล็อค สามารถแก้ไขและเซฟซ้ำได้ตลอดเวลา
ขั้นตอนการยืนยันล็อค / ปลดล็อค
4
ยืนยันล็อคทีเดียว: เมื่อกรอกตัวเลขครบถ้วนและตรวจทานความถูกต้องเรียบร้อยแล้ว ให้กดปุ่ม ยืนยันล็อคเดือนนี้
5
กดยืนยันในกล่องข้อความเตือน ข้อมูลประจำเดือนนั้นจะเปลี่ยนสถานะเป็น ล็อคแล้ว ทันที ช่องจะกลายเป็นสีเทาและไม่อนุญาตให้แก้ไขอีกต่อไป
6
การปลดล็อค: หากมีกรณีจำเป็นต้องแก้ไขย้อนหลัง ให้ผู้มีสิทธิ์ระดับ Admin หรือ Sale Sup กดปุ่ม ปลดล็อคเดือนนี้ เพื่อเปิดให้กลับมาแก้ไขได้ใหม่
5. สรุปผลการทดสอบระบบ (Test Results)
  • ทดสอบการบันทึกโดยไม่ล็อค: จำลองการส่งคำสั่ง Save ค่า target_qty_month และ forecast_qty_month_1 ผลคือฐานข้อมูลอัปเดตตัวเลขถูกต้อง 100% และสถานะ is_locked ยังคงเป็น 0 (ไม่ล็อค)
  • ทดสอบการบันทึกซ้ำ: สามารถแก้ไขตัวเลขและกดบันทึกต่อได้ทันทีโดยไม่ถูกบล็อก
  • ทดสอบการยืนยันล็อคทีเดียว: สั่ง Lock ผ่าน API ผลคือ is_locked ถูกปรับเป็น 1 พร้อมระบุ locked_at และ locked_by ครบถ้วน
  • ทดสอบ Backend Guard: เมื่อแถวมีสถานะ is_locked = 1 หากพยายามบันทึกข้อมูลโดยไม่ใช่สิทธิ์ Admin ระบบจะปฏิเสธการแก้ไขทันที
  • ทดสอบปุ่มปลดล็อค: Admin สั่ง Unlock ระบบรีเซ็ตสถานะ is_locked = 0 และเปิดช่องให้คีย์แก้ไขได้ตามปกติ
  • PHP Syntax Lint: ตรวจสอบไฟล์ PHP ทั้ง 8 ไฟล์ผ่านคำสั่ง php -l ผลผ่าน 100% ไม่มีข้อผิดพลาด
6. ระบบใหม่สำหรับแผนก Volume Tires (ตามไฟล์ template_v_tires.xlsx)
งานคนละแผนก
แยกหน้าจอและฐานข้อมูลอิสระสำหรับ Volume Tires

เนื่องจากไฟล์ template_v_tires.xlsx เป็นของแผนก Volume Tires ซึ่งมีรูปแบบคอลัมน์ 18 คอลัมน์ (A ถึง R) และมีตัวชี้วัดเรื่อง Volume (ลบ.ม.) โดยเฉพาะ ระบบจึงถูกสร้างแยกเป็นอิสระ เพื่อไม่ให้ปะปนกับยางเล็กและยางใหญ่เดิม

หน้าจอหลัก
forecast_plan_display_volume_tires.php

ตารางฐานข้อมูล
ims_tires_plan_forecast_volume_tires

import_forecast_volume_tires_process.php

จุดเด่นระบบ Volume Tires:
  • Smart Customer Match: ดึงรหัสลูกค้า AR_CODE อัตโนมัติจากชื่อลูกค้าใน Excel แม้มีวงเล็บชื่อร้าน เช่น คุณจักรพงค์ ชัยถาวรกิจ (ร้าน SK ไทร์เซอร์วิส 2014) → SAC.0000439
  • Smart Product & Volume Match: ค้นหาและจับคู่รหัสสินค้า SKU_CODE, ยี่ห้อ BRAND, ประเภท SKU_CAT และ VOLUME จากฐานข้อมูล m_volume_tires และ ims_product อัตโนมัติ
  • ระบบบันทึก & ล็อคมาตรฐานเดียวกัน: บันทึกแถวได้อิสระโดยยังไม่ล็อค และกดยืนยันล็อคทั้งเดือนเมื่อพร้อม ปลดล็อคได้โดย Admin
