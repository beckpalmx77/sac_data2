คู่มือการดึงข้อมูลยอดขายจริงจาก ims_data_sale_sac_all มาแทนการ Import

แนวทางนี้จะช่วยให้หน้าจอ forecast_plan_display.php แสดงผลยอดขายที่ "สดใหม่" (Live) เสมอ โดยการดึงตัวเลขมาจากฐานข้อมูลธุรกรรมโดยตรง แทนการใช้ตัวเลขคงที่จากไฟล์ Excel

1. โครงสร้าง SQL ที่ต้องใช้ (Query Structure)

เราจะใช้เทคนิค Conditional Aggregation (CASE WHEN) เพื่อรวมยอดขายตามเงื่อนไขเวลาที่ต้องการในคำสั่งเดียว:

SELECT SKU_CODE, AR_CODE, -- ยอดขายย้อนหลัง 3 เดือน SUM(CASE WHEN DI_MONTH = 1 AND DI_YEAR = 2024 THEN TRD_QTY ELSE 0 END) as sales_m1, SUM(CASE WHEN DI_MONTH = 2 AND DI_YEAR = 2024 THEN TRD_QTY ELSE 0 END) as sales_m2, SUM(CASE WHEN DI_MONTH = 3 AND DI_YEAR = 2024 THEN TRD_QTY ELSE 0 END) as sales_m3, -- ค่าเฉลี่ยปีก่อนหน้า (ทั้งปี / 12) SUM(CASE WHEN DI_YEAR = 2023 THEN TRD_QTY ELSE 0 END) / 12 as last_year_avg FROM ims_data_sale_sac_all WHERE AR_CODE = 'SACXXX' AND SKU_CODE = 'SKUXXX' GROUP BY SKU_CODE, AR_CODE

2. วิธีการคำนวณ (Calculation Logic)

รายการ สูตรการคำนวณ (Live Calculation)
ยอดขายย้อนหลัง (M-1, M-2, M-3) ดึงจากผลรวมของฟิลด์ TRD_QTY ในตาราง ims_data_sale_sac_all ตามเดือนและปีที่ระบุ
ค่าเฉลี่ย 12 เดือนปีก่อนหน้า
LastYearSum / 12
ค่าเฉลี่ย 3 เดือน (ย้อนหลัง)
(sales_m1 + sales_m2 + sales_m3) / 3

(ใช้ฟังก์ชันปัดเศษ: เศษ >= 0.5 ปัดขึ้น, < 0.5 ปัดลง)
เทียบคาดการณ์ยอดขาย (%)
((Forecast - Avg3M) / Avg3M) * 100

3. ขั้นตอนการลงมือทำ (Implementation Steps)

ขั้นตอนที่ 1: แก้ไขไฟล์ forecast_plan_fetch.php

เปลี่ยนจากการ Query SELECT * FROM ims_tires_plan_forecast เพียงอย่างเดียว เป็นการ LEFT JOIN กับยอดขายจริง:

  1. สร้าง SQL ย่อย (Sub-query) เพื่อหาผลรวมยอดขายจาก ims_data_sale_sac_all
  2. Join กับตารางหลัก ims_tires_plan_forecast โดยใช้ AR_CODE และ SKU_CODE เป็นตัวเชื่อม (Key)
  3. นำค่าจากผล Join มาแสดงแทนค่าที่อยู่ในตารางหลัก

ขั้นตอนที่ 2: การจัดการเดือนย้อนหลังใน PHP

ใช้ Logic ในการคำนวณเดือนย้อนหลังอัตโนมัติ เพื่อส่งเข้าไปใน SQL:

$target_month = 6; // เดือนที่กำลังวางแผน $m1 = $target_month - 1; if($m1 <= 0) { $m1 += 12; $y1 = $year-1; } $m2 = $target_month - 2; // ... คำนวณถอยหลังไปเรื่อยๆ ...

ขั้นตอนที่ 3: ปรับปรุงการแสดงผล (UI Synchronization)

  • แก้ไขหน้าจอให้แสดง Live Data ในคอลัมน์ยอดขาย
  • เมื่อผู้ใช้แก้ค่าในช่อง Target (เป้าหมาย) หรือ Forecast (คาดการณ์) ระบบจะนำค่า "ยอดขายจริง" ที่เพิ่งดึงมาได้ ไปคำนวณหา % ต่างๆ ทันที
ข้อควรระวัง: การ JOIN ข้อมูลขนาดใหญ่ใน ims_data_sale_sac_all อาจทำให้หน้าจอโหลดช้าลง แนะนำให้สร้าง Index ที่ฟิลด์ AR_CODE, SKU_CODE, DI_MONTH และ DI_YEAR ในฐานข้อมูลเพื่อประสิทธิภาพสูงสุด
