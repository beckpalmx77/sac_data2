การปรับปรุงประสิทธิภาพการโหลดข้อมูลเริ่มต้น (Initial Load Optimization)

เนื่องจากการดึงข้อมูลในหน้าจอ Tires Plan Forecast (Interactive) มีการเชื่อมโยงกับยอดขายจริงจากฐานข้อมูลขนาดใหญ่ ซึ่งทำให้การโหลดหน้าจอครั้งแรกที่มีข้อมูลทั้งหมดทำได้ช้ามาก จึงได้ดำเนินการปรับปรุงดังนี้:

1. การปรับปรุงฝั่ง Server (forecast_plan_fetch_new.php)

เพิ่มเงื่อนไขการตรวจสอบพารามิเตอร์ เดือน (Month) และ ปี (Year) ก่อนเริ่มการประมวลผล SQL:

// หากไม่มีการระบุเดือนและปี ให้ส่งค่าว่างกลับทันทีเพื่อประหยัดทรัพยากร if (empty($month) && empty($year)) { echo json_encode([ "draw" => intval($_POST['draw']), "recordsTotal" => 0, "recordsFiltered" => 0, "data" => [] ]); exit; }

ผลที่ได้: ระบบจะไม่ทำการคำนวณยอดขายย้อนหลัง (Subquery) ที่ซับซ้อนหากผู้ใช้ยังไม่ได้ระบุเงื่อนไขการกรอง

2. การปรับปรุงฝั่ง UI (forecast_plan_display_new.php)

  • Dropdown Default: เปลี่ยนค่าเริ่มต้นของ "เดือน" และ "ปี" ให้เป็น "-- เลือกเดือน --" และ "-- เลือกปี --" (ค่าว่าง)
  • Empty Table: เมื่อเปิดหน้าจอขึ้นมา ตาราง DataTables จะแสดงเป็นตารางว่าง (Zero Records) ทันทีแทนการโหลดข้อมูลทั้งหมด
  • Filter Requirement: ผู้ใช้งานต้องทำการเลือก เดือน และ ปี ที่ต้องการก่อน แล้วจึงกดปุ่ม "กรองข้อมูล" เพื่อดึงข้อมูลเฉพาะส่วนที่ต้องการออกมา

3. ประโยชน์ที่ได้รับ

  1. Page Load Speed: หน้าจอเปิดขึ้นมาได้ทันทีโดยไม่ต้องรอการประมวลผลข้อมูล
  2. Server Performance: ลดภาระการทำงานของ Database Server ในการ Query ข้อมูลที่ไม่ได้ใช้งาน
  3. User Experience: ผู้ใช้งานสามารถเจาะจงดูข้อมูลที่สนใจได้โดยตรง ช่วยลดความสับสนจากข้อมูลที่มากเกินไป
ข้อแนะนำ: หากระบบยังคงช้าหลังจากการกรองข้อมูลแล้ว แนะนำให้ตรวจสอบการสร้าง Index ในตาราง ims_data_sale_sac_all และ ims_tires_plan_forecast เพื่อเพิ่มความเร็วในการ JOIN ข้อมูล
