ภาพรวมการปรับปรุงระบบ Tires Plan Forecast สู่ระบบ Interactive & Live Data

เอกสารฉบับนี้สรุปแนวทางการปรับปรุงหน้าจอ forecast_plan_display.php โดยเริ่มต้นจากจุดเริ่มต้นที่สำคัญคือ forcast_month และ forcast_year ที่ผู้ใช้งานระบุไว้ตั้งแต่ขั้นตอนการนำเข้าไฟล์ Excel

1. วงจรการทำงานของระบบใหม่ (The New Workflow)

1. นำเข้า (Import)
ระบุเดือน/ปี วางแผน
➔
2. ดึงข้อมูล (Fetch)
ดึงยอดขายจริงจาก DB
➔
3. ปรับแต่ง (Edit)
แก้ไขและคำนวณสด
➔
4. บันทึก (Save)
บันทึกลงฐานข้อมูล

2. หลักการคำนวณแบบ Dynamic (Dynamic Lookup Logic)

ระบบจะใช้ forcast_month เป็นตัวตั้งต้น (Anchor) เพื่อย้อนหาช่วงเวลาของยอดขายจริงโดยอัตโนมัติ:

ตัวอย่าง: หากวางแผนเดือน 6 (มิถุนายน) 2024 ระบบจะคำนวณอัตโนมัติดังนี้:
  • M-1 (เดือนก่อนหน้า): เดือน 5 (พฤษภาคม) 2024
  • M-2: เดือน 4 (เมษายน) 2024
  • M-3: เดือน 3 (มีนาคม) 2024
  • Last Year: ปี 2023 (หาค่าเฉลี่ย 12 เดือน)

3. รายละเอียดการเปลี่ยนแปลงทางเทคนิค

ส่วนประกอบ เดิม (Static) ใหม่ (Interactive & Live)
แหล่งข้อมูลยอดขาย ดึงจากคอลัมน์ในตารางที่นำเข้าจาก Excel JOIN ยอดขายจริง จากตาราง ims_data_sale_sac_all
การแสดงผลตาราง เป็นข้อความธรรมดา (Text) เป็นกล่องข้อความ (Input Box) ในคอลัมน์ที่ต้องแก้ไข
การคำนวณ % ต่างๆ ค่าคงที่ (Static) คำนวณใหม่ทุกครั้งที่พิมพ์ตัวเลขด้วย JavaScript
การบันทึกข้อมูล ต้องแก้ใน Excel แล้ว Import ใหม่ กดปุ่ม Save บันทึกลง Database ได้ทันที

4. ผลลัพธ์ที่ได้รับ (Expected Outcome)

  • ความแม่นยำ: ข้อมูลยอดขายย้อนหลังจะตรงกับความเป็นจริงในระบบบัญชีเสมอ
  • ความรวดเร็ว: เซลส์หรือผู้บริหารสามารถ "จำลองตัวเลข" (Simulate) เพื่อดูผลกระทบต่อเป้าหมายได้ทันทีบนหน้าเว็บ
  • ความคล่องตัว: ลดขั้นตอนการทำงานกับไฟล์ Excel ที่ซับซ้อนและลดโอกาสเกิดข้อผิดพลาดจากการคัดลอกข้อมูล
* สำหรับรายละเอียดเชิงลึกและขั้นตอนการเขียนโค้ด สามารถดูได้ที่ไฟล์ plan_method_change_how_to.html
