แผนการเพิ่มระบบสรุปยอดตามยี่ห้อ (Brand Summary)
[อัปเดตล่าสุด: ระบบความปลอดภัยและการกรองข้อมูล]

วัตถุประสงค์

เพิ่มความสามารถในการรวมยอดคำนวณแยกตามยี่ห้อ (Brand) ในหน้าจอ forecast_plan_display_new.php โดยมุ่งเน้นความถูกต้องของข้อมูลตามสิทธิ์การเข้าถึง และความสอดคล้องกับตัวกรองหลัก

! การควบคุมสิทธิ์และการกรองข้อมูล (Critical)

ความปลอดภัยเป็นลำดับแรก: การดึงข้อมูลสรุปต้องตรวจสอบ account_type จาก Session ทุกครั้งเพื่อให้แน่ใจว่า:
  • Admin: สามารถดูยอดสรุปได้ทั้งหมดทุกยี่ห้อ ทุกเซลส์ ทุกลูกค้า
  • Sale User: ดูได้เฉพาะยอดสรุปในส่วนที่ตนเองเป็นพนักงานขาย (sale_name = session.first_name)
  • Take User: ดูได้เฉพาะยอดสรุปในส่วนที่ตนเองเป็นคนเทค (take_name = session.first_name)
การกรองข้อมูลแบบ Real-time: ยอดใน Modal ต้องเปลี่ยนตาม Filter ที่ผู้ใช้เลือกหน้าจอหลัก (เดือน, ปี, ชื่อพนักงาน, ชื่อลูกค้า) เพื่อให้ยอดรวม "ตรงกัน" กับรายการที่แสดงในตารางหลัก

1 การปรับปรุง UI (User Interface)

  • แทรกปุ่ม "สรุปยอดตามยี่ห้อ" (สีเหลืองหรือสีฟ้า) ถัดจากปุ่มกรองข้อมูล
  • เพิ่ม Bootstrap Modal โครงสร้างตารางประกอบด้วย:
    - ยี่ห้อ, เฉลี่ย 12ด., ยอดขาย M-1/M-2/M-3, เฉลี่ย 3ด., วางแผนการขาย, % เทียบวางแผนการขาย

2 ตรรกะการดึงข้อมูล (Backend Logic)

สร้างไฟล์ forecast_fetch_brand_summary.php เพื่อคำนวณยอดด้วย SQL:

  • ใช้คำสั่ง SUM() สำหรับทุกคอลัมน์ที่เป็นตัวเลข
  • ใช้คำสั่ง GROUP BY brand_code
  • หัวใจสำคัญ: ต้องมี WHERE clause ที่รองรับทั้ง account_type และเงื่อนไขจากตัวกรองหน้าเว็บ

3 ขั้นตอนการดำเนินการ

  1. Backend: พัฒนา API สำหรับสรุปยอดที่รองรับการเช็ค Session และสิทธิ์การเข้าถึง
  2. Frontend (HTML): เพิ่ม Modal Template ใน forecast_plan_display_new.php
  3. Frontend (JS): เขียนฟังก์ชันส่งค่า Filter ปัจจุบันไปยัง API และรับผลลัพธ์มา Render ลงใน Modal
  4. Validation: ตรวจสอบยอดรวมใน Modal เทียบกับยอดรวมในตารางหลักเพื่อให้มั่นใจว่า Logic ถูกต้อง
ข้อสรุป: การอัปเดตครั้งนี้จะเน้นที่ความปลอดภัยของข้อมูลเป็นหลัก โดยใช้ account_type เป็นตัวกำหนดขอบเขตข้อมูล (Data Scope) เพื่อป้องกันไม่ให้พนักงานเห็นข้อมูลของผู้อื่นในขณะดูยอดสรุป
