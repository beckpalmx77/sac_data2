1

การเปลี่ยนแปลง Type System ใน PHP 8.1 เป็นต้นไป

ใน PHP เวอร์ชัน 7.x เมื่อส่งค่า null เข้าไปยังฟังก์ชัน Built-in เช่น preg_replace(), str_replace(), trim(), strlen() ตัว PHP Engine จะทำการ Type Cast แปลง null ให้เป็นสตริงว่าง ("") โดยอัตโนมัติอย่างเงียบๆ
แต่ตั้งแต่ **PHP 8.1** เป็นต้นไป PHP ได้เข้มงวดเรื่อง Type System มากขึ้น โดยไม่อนุญาตให้ส่ง null ให้กับพารามิเตอร์ที่รับเฉพาะ string|array หากส่ง null จะสร้างคำเตือนระดับ E_DEPRECATED ทันที

2

ผลกระทบต่อเนื่องเมื่อเปิดใช้งาน Xdebug

เนื่องจากเครื่องเซิร์ฟเวอร์เปิดใช้งาน Xdebug 3.5.3 เมื่อเกิดข้อความ Deprecation ทาง Xdebug จะเรนเดอร์แท็กตาราง HTML <table class='xdebug-error xe-deprecated'>...</table> ออกมายัง Output Stream ทันที
ซึ่งในกรณีของไฟล์ Export CSV นั้น มีการตั้งค่า Header เป็น Content-type: text/csv จึงทำให้ตารางข้อผิดพลาด HTML แทรกเข้าไปในเนื้อหาไฟล์ CSV ส่งผลให้ไฟล์เสียหาย (Corrupted) หรือเปิดไม่ได้

3

ต้นตอของข้อมูล Null จาก Database

ในไฟล์สคริปต์ ดึงข้อมูล $original_remark = $row['DI_REMARK']; โดยเรคคอร์ดของใบสั่งขายบางรายการไม่มีหมายเหตุ หรือในฐานข้อมูลเก็บเป็น NULL เมื่อส่งตัวแปรนี้เข้า preg_replace('/[\r\n]+/', ' ', $original_remark) จึงเกิดข้อผิดพลาดดังกล่าว

แนวทางปฏิบัติที่ดี (Best Practices สำหรับ PHP 8.1 - 8.3+)

1. ใช้ Null Coalescing Operator (?? '') เสมอ

ฟิลด์จากฐานข้อมูลที่อนุญาตให้เป็น NULL (Nullable Columns) เช่น หมายเหตุ, ชื่อสาขา, รหัสอ้างอิง ควรกำหนดเป็น $row['COLUMN'] ?? '' เสมอ เพื่อให้การเรียกฟังก์ชันสตริง เช่น preg_replace(), str_replace(), trim(), strlen() ทำงานได้อย่างปลอดภัยและไม่มีข้อความเตือน

2. การแปลง Type อย่างชัดเจน (Explicit Type Casting)

ในกรณีที่รับตัวแปรที่ไม่แน่ใจประเภท สามารถใช้ trim((string)$str) เพื่อบังคับ Type เป็นสตริงก่อนเสมอ ป้องกัน Type Error และ Deprecation ได้ทุกกรณี

3. การจัดการ Error Reporting ในไฟล์ Export

สำหรับไฟล์ที่ทำหน้าที่ Stream ดาวน์โหลด CSV หรือ PDF หากเกิดข้อผิดพลาดระดับ Notice/Deprecated การเปิด display_errors อาจทำให้ตาราง Error ถูกส่งปนไปกับเนื้อหาไฟล์ จึงแนะนำให้มั่นใจว่าข้อมูลไม่มีค่า null หรือกำหนด error_reporting(E_ALL & ~E_DEPRECATED); ใน Environment ที่จำเป็น
