1. ผลการตรวจสอบระบบ Session ของโปรเจกต์ sac_data2

สรุปผลการตรวจสอบไฟล์ซอร์สโค้ดและสภาพแวดล้อม PHP ของระบบในปัจจุบัน

จากการตรวจสอบโค้ดทั้งหมดในโปรเจกต์ sac_data2 และสภาพแวดล้อมรันไทม์ของ PHP พบข้อสรุปดังนี้:

รายการตรวจสอบ สถานะปัจจุบันในโปรเจกต์ ผลกระทบ / สิ่งที่ต้องปรับปรุง
PHP Version & Environment PHP 8.3.14 (Visual C++ 2019 x64) บน WAMP / Windows รองรับการติดตั้งส่วนขยาย phpredis ได้ทันที
Session Save Handler session.save_handler = files เก็บเป็นไฟล์เดี่ยว ไม่สามารถแชร์ข้าม 2 เครื่องได้
Session Save Path session.save_path = d:/wamp64/tmp ไฟล์ Session ผูกติดกับ Local Disk ของเครื่องนั้นๆ เท่านั้น
Redis Service (Port 6379) ไม่มี Service หรือ Daemon รันอยู่ (TcpTest: False) ต้องติดตั้งและรัน Redis Server ขึ้นมาใช้งาน
Redis PHP Extension ไม่มีโมดูล redis ในผลลัพธ์ของ php -m ต้องเปิดใช้งาน php_redis.dll (Windows) หรือ php8.3-redis (Linux)
Composer Dependencies ไม่มี predis/predis ใน composer.json แนะให้ใช้ Native Extension (phpredis) ผ่าน php.ini เพราะเร็วกว่ามาก
โครงสร้างการเรียก Session เรียก session_start(); ตรงๆ มากกว่า 80 ไฟล์ ข้อดี หากคอนฟิกผ่าน php.ini จะทำงานได้ทันทีโดยไม่ต้องแก้โค้ดเลย
การตรวจสอบ IP ผู้ใช้ มีฟังก์ชัน getClientIP() ใน util/network.php รองรับ HTTP_X_FORWARDED_FOR พร้อมแล้ว สามารถรันหลัง Load Balancer ได้โดยได้ IP จริงของผู้ใช้
ปัญหาที่จะเกิดขึ้นทันทีเมื่อนำ 2 Server ไปใช้งานโดยไม่มี Redis Session Store

เมื่อมี 2 เครื่อง (Server A และ Server B) วางอยู่หลัง Load Balancer:
1. ผู้ใช้กดล็อกอินที่ Server A → ข้อมูล $_SESSION['alogin'] ถูกบันทึกลงไฟล์บนดิสก์ของ Server A
2. ผู้ใช้กดคลิกดูเมนูถัดไป Load Balancer ส่ง Request ไปยัง Server B
3. Server B หาไฟล์ session ไม่พบ ทำให้ตัวแปร $_SESSION['alogin'] ว่างเปล่า!
4. บรรทัด if (strlen($_SESSION['alogin']) == "") { header("Location: index.php"); } ใน Dashboard_admin.php จะเตะผู้ใช้ออกจากระบบทันที ทำให้เกิดอาการ "ล็อกอินแล้วเด้งออกตลอดเวลา (Session Drop / Random Logout)"

2. สถาปัตยกรรมระบบ 2 Server ร่วมกับ Redis Session Store

ออกแบบการจัดวางระบบเครือข่ายและการจัดเก็บ Session กลาง (Centralized Session Cluster)

การใช้งานระบบ 2 Servers จะต้องมีตัวกลางในการเก็บสถานะ Session เพื่อให้ทั้งสองเครื่องอ่านและเขียนชุดข้อมูลเดียวกันแบบ Real-time ด้วยความเร็วสูงระดับ Microseconds (In-Memory RAM):

เปรียบเทียบ 2 ทางเลือกในการจัดวางเครื่อง Redis (Deployment Topology)

แบบที่ 1: ติดตั้ง Redis บน Server 1 แนะนำ (ประหยัดสุด)

ใช้ Server 1 เป็นทั้ง Web App Node 1 และติดตั้ง Redis Service ไว้ในเครื่องเดียวกัน จากนั้นให้ Server 2 เชื่อมต่อเข้ามายัง Redis ของ Server 1 ผ่าน LAN/Private IP

  • ไม่ต้องเช่าเครื่อง Server ที่ 3 (ประหยัดค่าใช้จ่าย)
  • Server 1 อ่าน Session ภายในเครื่องได้เร็วที่สุด (localhost)
  • เหมาะสมอย่างยิ่งสำหรับระบบขนาดกลางและงบจำกัด
  • หาก Server 1 ดับ Server 2 จะใช้งาน Session ไม่ได้

แบบที่ 2: ใช้ Redis แยกเครื่องต่างหาก Enterprise

แยกเครื่อง Redis ไว้อีก Node หนึ่ง (หรือใช้ Managed Redis เช่น AWS ElastiCache / Redis Cloud) โดยทั้ง Server 1 และ Server 2 ทำหน้าที่เป็น Stateless Web Nodes อย่างแท้จริง

  • แยก Workload ออกจาก Web Server อย่างเด็ดขาด
  • Web Server เครื่องใดเครื่องหนึ่งพัง อีกเครื่องทำงานต่อได้ 100%
  • รองรับการขยายเป็น 3, 4, 5 Servers ได้อย่างราบรื่น
  • ต้องมี Server ที่ 3 หรือมีค่าบริการ Cloud เพิ่มเติม

3. การติดตั้งและตั้งค่า Redis Server (ความปลอดภัย & ประสิทธิภาพ)

ขั้นตอนการติดตั้ง Redis Daemon และการปรับแต่งไฟล์คอนฟิกให้ปลอดภัยสำหรับการเชื่อมต่อข้ามเครื่อง

1

ติดตั้ง Redis Service บนเซิร์ฟเวอร์

เลือกติดตั้งตามระบบปฏิบัติการของโฮสต์ที่ทำหน้าที่เป็น Redis Master:

Bash Terminal (Ubuntu/Debian) 
# 1. อัปเดตและติดตั้ง Redis Server
sudo apt update
sudo apt install redis-server -y

# 2. สั่งให้ Service ทำงานและเปิดใช้งานตอนเปิดเครื่อง
sudo systemctl enable redis-server
sudo systemctl start redis-server
Bash Terminal (RHEL / Rocky Linux) 
# 1. ติดตั้ง EPEL Repository และ Redis
sudo dnf install epel-release -y
sudo dnf install redis -y

# 2. สั่งให้ Service ทำงาน
sudo systemctl enable redis
sudo systemctl start redis
Windows PowerShell / Service 
# สำหรับ Windows Server แนะนำให้ใช้ตัวเลือกใดตัวเลือกหนึ่ง:
# ทางเลือก A: ติดตั้ง Redis ผ่าน WSL2 (Ubuntu on Windows) - แนะนำอย่างยิ่งสำหรับ Production
wsl --install -d Ubuntu
sudo apt install redis-server

# ทางเลือก B: ติดตั้งผ่าน Native Windows Port (เช่น Memurai หรือ Redis-x64 MSI)
# ดาวน์โหลดติดตั้ง Service ให้พร้อมทำงานบน Port 6379
2

ปรับแต่งไฟล์คอนฟิก redis.conf

เปิดไฟล์คอนฟิก (เช่น /etc/redis/redis.conf บน Linux) และปรับแต่งค่าพารามิเตอร์เพื่อความปลอดภัยและการจัดการ RAM:

redis.conf (Security & Performance) 
# -------------------------------------------------------------
# 1. เครือข่าย: อนุญาตให้เรียกจาก localhost และ IP วงใน (LAN)
# ห้ามใส่ 0.0.0.0 สู่ Public Internet เด็ดขาด!
# สมมุติ IP เครื่องนี้ในวงแลนคือ 192.168.1.10
# -------------------------------------------------------------
bind 127.0.0.1 192.168.1.10
protected-mode yes
port 6379

# -------------------------------------------------------------
# 2. ความปลอดภัย: ตั้งรหัสผ่านที่รัดกุม (ห้ามเว้นว่าง)
# -------------------------------------------------------------
requirepass "SacSecureRedisSession2026!#Pass"

# -------------------------------------------------------------
# 3. การจัดการหน่วยความจำสำหรับ Session Store (สำคัญมาก)
# -------------------------------------------------------------
# กำหนดเพดาน RAM สูงสุดที่ยอมให้ Redis ใช้ (เช่น 512MB หรือ 1GB)
maxmemory 512mb

# เมื่อ RAM เต็ม ให้ลบเฉพาะ Key ที่มีอายุหมดเวลา (Session ที่หมดอายุ)
maxmemory-policy volatile-ttl

# -------------------------------------------------------------
# 4. ประสิทธิภาพ: ปิดการเซฟลง Disk หรือเซฟแบบ AOF ทุก 1 วินาที
# -------------------------------------------------------------
appendonly yes
appendfsync everysec
คำเตือนเรื่องความปลอดภัยขั้นสูงสุด!

ห้ามเปิด Port 6379 สู่ Public IP หรือ Internet สาธารณะโดยเด็ดขาด การเชื่อมต่อระหว่าง Web Server 1 & Web Server 2 กับ Redis จะต้องทำผ่าน Private Network (LAN / VPC) เท่านั้น

3

ตั้งค่า Firewall จำกัดสิทธิ์เฉพาะ Server 1 และ Server 2

เปิด Port 6379 ให้เฉพาะ IP ของ Web Server เท่านั้น ป้องกันบุคคลภายนอกเข้าถึง:

UFW Firewall Rules (Ubuntu/Debian) 
# อนุญาตเฉพาะ Web Server 1 (192.168.1.11)
sudo ufw allow from 192.168.1.11 to any port 6379 proto tcp

# อนุญาตเฉพาะ Web Server 2 (192.168.1.12)
sudo ufw allow from 192.168.1.12 to any port 6379 proto tcp

# ตรวจสอบสถานะไฟร์วอลล์
sudo ufw status verbose

# รีสตาร์ท Redis Service เพื่อปรับใช้คอนฟิก
sudo systemctl restart redis-server

4. การตั้งค่า PHP บนทั้ง 2 เครื่อง (Zero-Code Change Strategy)

ปรับแต่ง php.ini ให้โปรเจกต์ 80+ ไฟล์รองรับ Redis Session ทันทีโดยไม่ต้องแก้โค้ด

ทำไมต้องเลือกวิธี Zero-Code Change ผ่าน php.ini?

เนื่องจากโปรเจกต์ sac_data2 มีการเรียกฟังก์ชัน session_start(); กระจายอยู่มากกว่า 80 ไฟล์ หากเราตั้งค่า session.save_handler = redis ในระดับ php.ini ของเครื่อง เซิร์ฟเวอร์จะเปลี่ยนไปเก็บและอ่าน Session ผ่าน Redis ทันทีโดยอัตโนมัติ โดยไม่ต้องเข้าไปเปิดแก้ไขโค้ด PHP แม้แต่บรรทัดเดียว!

1

ติดตั้งโมดูล phpredis บน Web Server ทั้ง 2 เครื่อง

ต้องติดตั้ง Extension phpredis บนทั้ง Server 1 และ Server 2:

Terminal (Linux PHP 8.3) 
# ติดตั้งส่วนขยาย Redis สำหรับ PHP 8.3
sudo apt install php8.3-redis -y

# ตรวจสอบการโหลดโมดูล
php -m | grep redis
# ผลลัพธ์ต้องแสดงคำว่า: redis
Windows / WAMP Setup 
1. เข้าเว็บไซต์ PECL เพื่อดาวน์โหลด php_redis.dll สำหรับ PHP 8.3:
   https://pecl.php.net/package/redis (เลือกเวอร์ชัน 6.0+ x64 Thread Safe ให้ตรงกับ PHP)
2. นำไฟล์ php_redis.dll ไปวางไว้ที่โฟลเดอร์ ext:
   d:\wamp64\bin\php\php8.3.14\ext\php_redis.dll
3. เปิดไฟล์ php.ini และเพิ่มบรรทัด:
   extension=redis
4. รีสตาร์ท Apache ใน WampServer
2

ตั้งค่า Session Directives ในไฟล์ php.ini

เปิดไฟล์ php.ini (ทั้งบน Server 1 และ Server 2) ค้นหาส่วน [Session] แล้วแทนที่ค่าดังนี้:

php.ini Configuration 
[Session]
; 1. กำหนดให้ใช้ Redis เป็นตัวจัดการ Session แทนไฟล์
session.save_handler = redis

; 2. กำหนด Path เชื่อมต่อไปยัง Redis Server กลาง (เปลี่ยน IP และ Password ตามจริง)
; รูปแบบ: tcp://HOST:PORT?auth=PASSWORD&prefix=KEY_PREFIX&timeout=SECONDS
session.save_path = "tcp://192.168.1.10:6379?auth=SacSecureRedisSession2026!%23Pass&prefix=SAC_SESSION:&timeout=2.5"

; 3. การควบคุม Session Locking (ป้องกันปัญหา Race Condition ขนาน)
; เปิด Session Locking เพื่อไม่ให้ AJAX หลายตัวเขียนทับข้อมูลกันเอง
redis.session.locking_enabled = 1
redis.session.lock_expire = 300
redis.session.lock_wait_time = 20000
redis.session.lock_retries = 100

; 4. อายุของ Session (วินาที) - เช่น 1 วัน (86400 วิ)
session.gc_maxlifetime = 86400
session.cookie_lifetime = 86400

; 5. ความปลอดภัยของ Cookie Session
session.cookie_httponly = 1
session.cookie_samesite = "Lax"
session.use_strict_mode = 1
คำอธิบายพารามิเตอร์สำคัญ:

• prefix=SAC_SESSION: ตั้งชื่อ Prefix นำหน้าใน Redis เพื่อไม่ให้ชนกับระบบอื่น ค้นหาดูแลง่าย
• timeout=2.5: หาก Redis ไม่ตอบสนองภายใน 2.5 วินาที ให้ตัด timeout ทันที ป้องกันหน้าเว็บค้าง
• locking_enabled=1: โปรเจกต์นี้มีหน้าจอที่ยิง AJAX พร้อมกันหลายตัว (เช่น Datatables / Graph) การเปิด Lock จะช่วยให้ Session ไม่พังเมื่อโหลดหน้าจอพร้อมกัน

5. ทางเลือกเพิ่มเติม: การสร้างไฟล์ Session Bootstrap กลาง (Best Practice)

สร้างโมดูลจัดการ Session พร้อมระบบตรวจจับความผิดพลาด (Graceful Fallback & Health Check)

เพื่อความยืดหยุ่นในระดับโค้ด สามารถสร้างไฟล์คอนฟิก config/session.php และสามารถสั่งให้รันอัตโนมัติก่อนทุกสคริปต์ได้ด้วยคำสั่ง auto_prepend_file ใน php.ini:

config/session.php 
<?php
/**
 * SAC DATA 2 - Centralized Redis Session Handler
 * ป้องกันการเรียก session_start() ซ้ำซ้อน และจัดการ Connection สู่ Redis
 */

if (session_status() === PHP_SESSION_NONE) {
    // กำหนดค่า Security Cookie
    ini_set('session.cookie_httponly', 1);
    ini_set('session.use_only_cookies', 1);
    ini_set('session.cookie_samesite', 'Lax');

    // ถ้ายังไม่ได้ตั้งค่าใน php.ini สามารถกำหนดผ่านโค้ดตรงนี้ได้
    $redis_host = getenv('REDIS_HOST') ?: '192.168.1.10';
    $redis_port = getenv('REDIS_PORT') ?: 6379;
    $redis_pass = getenv('REDIS_PASS') ?: 'SacSecureRedisSession2026!#Pass';
    $redis_prefix = 'SAC_SESSION:';

    // ตรวจสอบว่าโมดูล phpredis ติดตั้งแล้วหรือไม่
    if (extension_loaded('redis')) {
        ini_set('session.save_handler', 'redis');
        $save_path = sprintf(
            'tcp://%s:%d?auth=%s&prefix=%s&timeout=2.0',
            $redis_host,
            $redis_port,
            urlencode($redis_pass),
            $redis_prefix
        );
        ini_set('session.save_path', $save_path);
    }

    // เริ่มต้น Session
    session_start();
}
เทคนิคการใช้งานผ่าน auto_prepend_file

หากไม่ต้องการไปตามแก้โค้ดในไฟล์ต่างๆ คุณสามารถระบุใน php.ini:
auto_prepend_file = "d:/website/sac_data2/config/session.php" (หรือ Path บน Linux)
PHP จะทำการรันไฟล์นี้ก่อนทุกไฟล์ทันที ทำให้ได้ Session Redis ทั่วทั้งระบบ 100%

6. การตั้งค่า Load Balancer (NGINX Reverse Proxy)

กระจายทราฟฟิกไปยัง 2 Web Servers พร้อมส่งต่อ IP ผู้ใช้งานจริงเข้าสู่ฟังก์ชัน getClientIP()

เมื่อทั้ง 2 เครื่องใช้ Redis Session ร่วมกันแล้ว Load Balancer จะสามารถกระจายโหลดแบบ Round Robin หรือ Least Connections ได้อย่างเต็มประสิทธิภาพโดยไม่มีปัญหา Session หลุด:

/etc/nginx/conf.d/sac_balancer.conf 
# 1. กำหนด Cluster ของ Web Server 2 เครื่อง
upstream sac_cluster {
    # กระจายแบบ Least Connections (ส่งไปเครื่องที่ทำงานเบากว่า)
    least_conn;

    server 192.168.1.11:80 max_fails=3 fail_timeout=10s;
    server 192.168.1.12:80 max_fails=3 fail_timeout=10s;
}

# 2. Virtual Host หน้าบ้าน
server {
    listen 80;
    listen 443 ssl http2;
    server_name sac-data.yourdomain.com;

    # SSL Configuration (Let's Encrypt / Cert)
    ssl_certificate /etc/ssl/certs/sac_cert.crt;
    ssl_certificate_key /etc/ssl/private/sac_cert.key;

    # Client Body Limit (รองรับการอัปโหลดไฟล์ขนาดใหญ่ เช่น Excel/ภาพ)
    client_max_body_size 64M;

    location / {
        proxy_pass http://sac_cluster;
        
        # -------------------------------------------------------------
        # ส่งต่อ Header สำคัญ (จำเป็นสำหรับ util/network.php getClientIP)
        # -------------------------------------------------------------
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket / Keepalive support
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';

        # Proxy Timeouts
        proxy_connect_timeout 60s;
        proxy_send_timeout 120s;
        proxy_read_timeout 120s;
    }
}

7. ข้อควรระวังเพิ่มเติมในการใช้งาน 2 Servers (Beyond Sessions)

จุดที่ต้องจัดการเพิ่มเติมเมื่อเปลี่ยนจากระบบเครื่องเดี่ยวเป็น 2 เครื่อง

โฟลเดอร์ Uploads รูปภาพ

ในโปรเจกต์นี้มีโฟลเดอร์ uploads/ และ img_checkin/ หากผู้ใช้อัปโหลดรูปผ่าน Server 1 แต่โหลดดูรูปจาก Server 2 รูปจะไม่แสดงผล!

แนวทางแก้ไข:

  • ใช้ NFS (Network File System) แชร์โฟลเดอร์ uploads/ ร่วมกัน
  • หรือตั้ง Lsyncd / Rsync Daemon Sync ไฟล์สองทางแบบ Real-time
  • หรือย้ายไปเก็บที่ S3 / Cloud Storage / MinIO

Cronjob & Scheduled Tasks

ในโปรเจกต์มีโฟลเดอร์ cronjob/ หากตั้ง Cronjob ไว้ที่ทั้ง 2 เครื่อง งานเบื้องหลังจะถูกรันซ้ำซ้อน 2 รอบ (Duplicate Processing)

แนวทางแก้ไข:

  • ตั้ง Cronjob ไว้ที่ Server 1 เครื่องเดียวเท่านั้น
  • หรือใช้ Redis Distributed Lock (SETNX) ล็อกไม่ให้รันงานซ้ำ

9. สรุปเช็คลิสต์ก่อนเปิดใช้งานระบบ 2 Servers (Pre-Flight Checklist)

ตรวจสอบความพร้อมทุกจุดก่อน Switch DNS หรือเปิดให้ผู้ใช้งานเข้าระบบ

Redis Service Ready

Redis ทำงานบน Port 6379, มีรหัสผ่าน, ตั้งค่า maxmemory-policy volatile-ttl เรียบร้อย

phpredis Loaded on Both Nodes

ทั้ง Server 1 และ 2 รันคำสั่ง php -m | grep redis แล้วเจอโมดูลเรียบร้อย

php.ini Session Save Handler

ทั้ง 2 เครื่องชี้ session.save_handler = redis ไปยัง IP เครื่อง Redis เดียวกัน

Firewall Lockdown

Port 6379 เข้าถึงได้เฉพาะ Private IP ของ Server 1 และ Server 2 เท่านั้น

Load Balancer IP Forwarding

Load Balancer มีการส่ง X-Forwarded-For เพื่อให้ getClientIP() ได้ IP จริง

Uploaded Assets Storage

โฟลเดอร์ uploads/ และ img_checkin/ ถูกแชร์หรือ Sync ระหว่างสองเครื่อง
