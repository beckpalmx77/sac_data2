ระบบจัดเก็บและวิเคราะห์ยอดขาย Siam Auto Car (sac_data2)

ระบบหลังบ้านที่เชื่อมโยงฐานข้อมูลการทำงานภายใน คลังสินค้า การออกรถขนส่ง ตารางตรวจเยี่ยมนัดพบลูกค้า CRM และเป้ายอดขายสินค้า ของบริษัท สงวนออโต้คาร์ จำกัด

1. ภาพรวมและเทคโนโลยีที่ใช้

ระบบ sac_data2 ทำหน้าที่หลักในการดึงข้อมูลดิบจาก ERP Business Plus (MS SQL Server) เพื่อมาประมวลผลคำนวณและแสดงผลในรูปแบบสรุปย่อ แผนภูมิ และสรุปยอดสะสม เพื่อให้ทีมผู้บริหารและฝ่ายขายนำไปประเมินเป้าและออกโปรแกรมรางวัลลูกค้าได้ทันที

เทคโนโลยีหลักที่ใช้ในการทำงาน (Stack):

PHP 8.x (PDO Object-oriented) MySQL 8.x (Local Database) MS SQL Server (ERP System Source) LINE Bot & Notify APIs jQuery / AJAX / Bootstrap

3. ตารางข้อมูลในฐานข้อมูล (Database Tables Explorer)

ฐานข้อมูลมีตารางข้อมูลหลายหมวดหมู่ เลือกหมวดหมู่หรือพิมพ์ค้นหาชื่อตารางที่ต้องการเพื่อหาบทบาทการทำงานในระบบ

ชื่อตาราง (MySQL Table Name) โมดูลระบบ คำอธิบายหน้าที่และบทบาทในระบบ
ims_user RBAC ตารางเก็บยูสเซอร์เข้าสู่ระบบ รหัสผ่านแบบ hashed และกำหนดประเภทบัญชี (Account Type)
ims_permission RBAC ตารางจับคู่ระหว่างระดับผู้ใช้ กับเมนูหลัก/เมนูย่อยที่เข้าถึงได้ รวมถึงหน้า Dashboard เริ่มต้น
menu_main / menu_sub RBAC เก็บไอคอน ลิงก์ปลายทาง ชื่อภาษาไทยและอังกฤษของเมนูข้างทางซ้ายมือทั้งหมด
ims_customer_crm CRM ข้อมูลลูกค้าสัมพันธ์ ที่อยู่ พิกัดภูมิศาสตร์ และแท็กประเภทร้านค้า
ims_customer_crm_check_header / detail CRM หัวข้อรายละเอียดการตรวจสุขภาพร้านค้า นัดเยี่ยม และรายงานบันทึกของเซลส์
checkins CRM พิกัดละติจูด/ลองจิจูดของพนักงานขาย เพื่อเช็กอินกับร้านค้าปลายทางตามวัน-เวลาจริง
ims_product_sale_sac SALES ข้อมูลธุรกรรมยอดขายรายวันของสงวนออโต้คาร์ ที่ดึงมาจาก MS SQL Server ERP
ims_sale_target SALES ตารางเก็บเป้าหมายรายเดือนของพนักงานขายแต่ละท่านสำหรับใช้คำนวณ Progress Bar
ims_sale_team SALES จับกลุ่มพนักงานขายภายใต้สังกัดหัวหน้าทีม เช่น แผนกค้าส่ง แผนกค้าปลีก
ims_tires_number TIRES เก็บรหัสซีเรียลนัมเบอร์ของยางแต่ละเส้น พร้อมประวัติการเข้าคลังและจำหน่ายออก
ims_tires_plan_forecast TIRES เก็บแผนการคาดการณ์ยอดขายยางเปรียบเทียบกับค่าเฉลี่ย 3 เดือน และเป้ายอดขายล่วงหน้า 2 เดือน
ims_sac_tires_point TIRES คะแนนสะสมของแต่ละร้านค้า สำหรับการซื้อยางบางแบรนด์เพื่อแลกสิทธิ์หรือของรางวัล
wh_warehouse / wh_location WMS ตารางระบุตัวตนคลังสินค้า และพิกัดระบุตำแหน่งเก็บสินค้า (Bin Locations)
wh_stock_transaction WMS ประวัติการเคลื่อนย้ายสินค้าทั้งหมดเข้า/ออก/โอนย้ายคลังรายรายการ
ims_sale_logistic_plan WMS แผนการขนส่งสินค้า จัดคิวรถคาร์โค้ด วันส่งของ และสถานะการจัดส่ง
aline_api INTEGRATION เก็บชุด Token และ Channel Key สำหรับเชื่อมการส่งข้อความผ่าน LINE API
log_line_send INTEGRATION บันทึกประวัติการยิง Push API ของระบบไปที่ LINE บอท เพื่อใช้วิเคราะห์กรณีส่งข้อความไม่ผ่าน

4. การเชื่อมโยงและนำเข้าข้อมูล (Data Sync Workflow)

ข้อมูลธุรกรรมหลัก (เช่น ยอดขาย บิลซื้อ รายการคลังสินค้า) จะถูกนำเข้าผ่านไฟล์สคริปต์คอมมานด์ในห้อง [`cronjob`](file:///D:/website/sac_data2/cronjob) เพื่อประมวลผลดึงข้อมูลข้ามเซิร์ฟเวอร์

1. Business Plus ERP (MS SQL Server)

ฐานข้อมูลธุรกรรมหลัก ณ เครื่องเซิร์ฟเวอร์หลัก (IP: 192.168.88.13)

2. CLI Cronjob Executed (.bat / .php)

เช็กประเภทใบสำคัญคัดเฉพาะรหัส DS02, IS01, IS02, IV01

3. Data Processing & Return Sign Checks

สคริปต์ตรวจหากพบประเภทการคืนของ (DT_PROPERTIES 308/337) จะทำการบังคับให้จำนวนค่าขายติดลบ

4. Target MySQL DB (sac_data2)

บันทึกผลลัพธ์ลงสู่ตาราง ims_product_sale_sac ทันทีเพื่อพร้อมพล็อตกราฟ

5. กฎระเบียบและข้อควรระวังสำหรับนักพัฒนา

  • ระบบความปลอดภัยการเข้าถึงหน้าเว็บ: หน้าเว็บหลักทุกหน้าจะถูกตรวจจับ Session เสมอ: 
    if (strlen($_SESSION['alogin']) == "") {
    header("Location: index.php");
}
    ในการสร้างไฟล์ใหม่ ต้องครอบเงื่อนไขนี้ที่บรรทัดบนสุดเสมอเพื่อป้องกันการลักลอบเปิดดูข้อมูลหลังบ้านโดยตรง
  • การป้องกันการฉีดโค้ดแปลกปลอม (SQL Injection Protection): ทุกการเขียนคิวรีฐานข้อมูล SQL ห้ามต่อสตริงตัวแปรเปล่าแบบดิบๆ ต้องทำการ Bind parameter ผ่าน PDO เสมอ
  • การเขียนบันทึกประวัติการส่งข้อมูลภายนอก: เมื่อเรียกใช้ LINE Message API ผ่านฟังก์ชันจากไฟล์ [`send_message.php`](file:///D:/website/sac_data2/util/send_message.php) ฟังก์ชันจะทำการเขียน Log ลงตาราง `log_line_send` อัตโนมัติ ห้ามนำฟังก์ชัน cURL ไปเขียนซ้ำซ้อนในหน้ารายงานย่อย
