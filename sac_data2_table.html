Stock Files & Data Sources
ตำแหน่งไฟล์ หน้าที่การทำงาน แหล่งข้อมูลที่ใช้งานอยู่ปัจจุบัน ใช้ ims_product_stock_balance? คำอธิบายเพิ่มเติม
export_process/export_data_stock_balance_all_process.php ประมวลผลส่งออกไฟล์ CSV สต็อกรวมแยกหมวด/แบรนด์ ⚡ MS SQL Server โดยตรง ❌ ไม่ได้ใช้ คิวรีสดจาก dbo.SKUMASTER ร่วมกับ dbo.SKUMOVE บน SQL Server
export_process/wh_export_data_stock_balance_all_process.php ประมวลผลส่งออกสต็อกคลังหลัก WH ⚡ MS SQL Server โดยตรง ❌ ไม่ได้ใช้ คิวรีสดจาก SQL Server ข้ามตาราง SKUMASTER, ICCAT, BRAND, SKUMOVE, WAREHOUSE
export_process/export_process_data_wh_stock_balance.php ประมวลผลส่งออกสต็อกคงเหลือคลัง WH MySQL (v_wh_stock_balance) ❌ ไม่ได้ใช้ คิวรีจาก Database View ใน MySQL ชื่อ v_wh_stock_balance
export_process/export_process_display_data_wh_stock_balance.php ส่งออกข้อมูลแสดงผลสต็อกคงเหลือ MySQL (wh_stock_transaction) ❌ ไม่ได้ใช้ คิวรีจาก wh_stock_transaction JOIN กับ wh_product_master
model/fetch_stock_balance.php API ดึงข้อมูลสต็อกคงเหลือสำหรับ DataTables MySQL (wh_stock_transaction) ❌ ไม่ได้ใช้ คำนวณยอด SUM(CASE record_type WHEN '+' THEN qty WHEN '-' THEN -qty) จาก wh_stock_transaction
display_stock_balance.php หน้าจอ UI รายงาน Stock Transaction Report AJAX (model/fetch_stock_balance.php) ❌ ไม่ได้ใช้ โหลดข้อมูลผ่าน DataTables AJAX ไปยัง fetch_stock_balance.php
manage-stock-balance.php หน้าจอจัดการสต็อกคงเหลือคลังสินค้า Form Submit -> export_process ❌ ไม่ได้ใช้ ส่งค่าแบบ POST ไปประมวลผลที่ export_process_data_wh_stock_balance.php

3. ไฟล์ที่พบการใช้งานตาราง ims_product_stock_balance ใน sac_data2

✅ พบ 3 ไฟล์ (ในโฟลเดอร์ cronjob/)

ในโปรเจกต์ d:\website\sac_data2 พบการใช้งานตารางนี้เฉพาะในส่วนงาน Background Process / Cronjob จำนวน 3 ไฟล์ ดังนี้:

# ตำแหน่งไฟล์ บรรทัดที่ ลักษณะการใช้งาน (Operation)
1 cronjob/delete_duplicates.php บรรทัด 17 กำหนด Keys ['SKU_CODE', 'WH_CODE', 'WL_CODE', 'DI_DATE'] สำหรับตรวจสอบและลบแถวข้อมูลที่ซ้ำกันในตาราง
2 cronjob/import_data_stock_balance.php บรรทัด 20, 27, 30, 34 ซิงค์ข้อมูลสต็อกจาก MS SQL Server เข้าสู่ MySQL ims_product_stock_balance (ตรวจสอบ Key ซ้ำ -> UPDATE หรือ INSERT)
3 cronjob/import_stock_movement.php บรรทัด 31, 47, 52 พรีโหลดข้อมูล SELECT และทำการ UPDATE / INSERT ข้อมูลความเคลื่อนไหวสต็อกล่าสุดเข้าตาราง ims_product_stock_balance
💡 ข้อสังเกตเชิงโครงสร้างของ sac_data2: ตาราง ims_product_stock_balance ใน sac_data2 ได้รับการซิงค์ข้อมูลอย่างต่อเนื่องผ่าน Cronjob 3 ไฟล์ข้างต้น และมีข้อมูลสมบูรณ์พร้อมอยู่แล้วถึง 52,587 รายการ แต่ส่วนงาน Export และ Frontend ใน export_process/ และ model/ ยังคงถูกเขียนแบบดั้งเดิมที่เรียกคิวรีตรงจาก MS SQL Server หรือคิวรีตาราง Transaction แทน

4. ข้อเสนอแนะเชิงเทคนิคเพื่อเพิ่มประสิทธิภาพ (Technical Recommendations)

Performance Tuning
  • เพิ่มความเร็วการ Export สต็อก (Export Optimization):
    ไฟล์ export_data_stock_balance_all_process.php และ wh_export_data_stock_balance_all_process.php ปัจจุบันต้องไปรันคำนวณยอด SUM(SKM_QTY) บน MS SQL Server สดทุกครั้งที่มีการกดดาวน์โหลด ซึ่งทำให้ใช้เวลาประมวลผลนาน สามารถปรับเปลี่ยนมา SELECT จากตาราง ims_product_stock_balance ใน MySQL ได้ทันที ซึ่งจะทำงานได้เร็วกว่าหลายเท่าตัว
  • ลดภาระฐานข้อมูลหลัก (Reduce SQL Server Load):
    การเปลี่ยนมาใช้ตาราง ims_product_stock_balance ใน MySQL จะช่วยปลดภาระการคำนวณของเซิร์ฟเวอร์ MS SQL Server หลัก ทำให้ระบบ ERP ใช้งานได้ลื่นไหล ไม่ติดปัญหา Database Lock หรือ CPU Spike ขณะมีผู้ใช้ดาวน์โหลดรายงานพร้อมกัน
